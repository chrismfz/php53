# PHP 5.3 for NGM — security-patched, source-built

This is the PHP **5.3.29** source tree NGM builds and runs as a legacy runtime,
kept alive safely past php.net's end-of-life. It is the pristine 5.3.29 source
plus:

- a self-contained build (`build-php53.sh`) that compiles into `/opt/ngm/php/5.3`
  against a **private OpenSSL 3.5 LTS** (legacy provider on), a **GnuTLS libcurl**
  (so `ext/curl` can't drag a second OpenSSL into the process), a pinned
  autoconf/bison/re2c toolchain, and the bundled **ionCube** loader — all under
  `/opt/ngm/php`, baked in by RPATH so they never collide with the host;
- a **security patch series backported by CloudLinux** and applied at build time.

NGM auto-discovers the result at `/opt/ngm/php/5.3/sbin/php-fpm`; nothing else on
the host is touched.

## Security patches — where they come from

CloudLinux keeps backporting security/bug fixes to EOL PHP and ships them, one
patch per fix, inside the **public** EA4 source RPMs at
`https://repo.cloudlinux.com/cloudlinux/EA4/`. We import the source security/bug
backports from there and drop the CloudLinux/LiteSpeed/EA4 runtime and
build-packaging patches we don't use.

- **`patches/`** — the imported series, verbatim, in apply order. Machine-owned:
  regenerated by the importer, never hand-edited. See **[`patches/README.md`](patches/README.md)**
  for the current source SRPM, the full CVE list, and the skip reasons.
- **`patches/series`** — the ordered list the build applies (`file -pN`).
- **`patches/MANIFEST.tsv`** — every applied SRPM patch, kept or skipped, with a
  sha256 and the reason.
- **`patches/SOURCE`** — exactly which SRPM the series was generated from.
- **`patches-local/`** — our hand-maintained overlay, which the importer never
  touches, so adaptations survive a refresh:
  - `exclude` — series entries we deliberately skip, each with a reason
    (e.g. a CVE already fixed by our OpenSSL 3.x rewrite).
  - `include` — patches to force-keep that the filename heuristic mis-scores as
    packaging (e.g. `p_option.patch`, which defines `CHECK_NULL_PATH`).
  - `*.patch` — our own adaptations, applied after the vendor series.

Current base: **`ea-php53-php-5.3.29-29.el8.cloudlinux.68`** (2026-08-17) —
320 patches applied (**151 CVEs**, through CVE-2026-14355), 1 excluded.

## Build

```sh
sudo FORCE=1 ./build-php53.sh
```

Useful env: `APPLY_PATCHES=0` builds pristine (no security series);
`RUN_REGRESSION_TESTS=0` skips the post-build suite;
`PHP_GIT_REF=<ref>` builds a specific branch/tag/commit.

## Refreshing to a newer CloudLinux release

The whole point of the import tooling is that a refresh is mechanical and the
delta is reviewable:

```sh
# 1. grab the newest SRPM (see patches/SOURCE for the current one)
curl -fSLO https://repo.cloudlinux.com/cloudlinux/EA4/8.1/updates/src/ea-php53-php-5.3.29-29.el8.cloudlinux.<NEW>.src.rpm

# 2. regenerate patches/ from it (deterministic — same SRPM => identical output)
./tools/import-cloudlinux-patches.py ea-php53-php-5.3.29-29.el8.cloudlinux.<NEW>.src.rpm

# 3. review ONLY the delta, then rebuild + test
git diff patches/      # new / changed / removed fixes, and any series reordering
```

New patches land as additions; a changed fix shows as a content diff (different
sha256); a removed one as a deletion. Re-check any `patches-local/exclude` entry
the delta touches, rebuild on a host, and merge.
